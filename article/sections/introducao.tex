\section{Introdução}

A crescente digitalização de serviços e a onipresença de dispositivos computacionais pessoais gera um volume de dados distribuídos sem precedentes,
o que impulsiona o desenvolvimento de soluções baseadas em aprendizado de máquina (ML).
Tradicionalmente, uma solução de ML exige que os dados estejam em um único dispositivo.
No entanto, os dados distribuidos geralmente devem permanecer nos seus dispositivos de origem por questões de privacidade.
Para superar esse obstáculo, o Aprendizado Federado (do inglês, \textit{Federated Learning} -- FL) surgiu como um paradigma
onde um servidor mantém um modelo global e distribui cópias para clientes selecionados na rede.
Nessa arquitetura, os dispositivos realizam o treinamento local com seus próprios dados e transmitem apenas as atualizações dos parâmetros.
O servidor então agrega essas contribuições via média ponderada (FedAvg) para atualizar o modelo global.
Todo esse processo se repete por diversas rodadas visando a convergência \cite{mcmahan2017communication, li2022federated}.

Apesar dos avanços que o FL proporcionou para sistemas de recomendação e para a área da saúde,
sua eficácia é frequentemente desafiada pela heterogeneidade estatística dos dados nos clientes (dados não-IID).
Essa heterogeneidade impacta negativamente a agregação, tornando o modelo global subótimo para a maioria dos participantes.
Com o objetivo de solucionar esse problema, uma linha de pesquisa proeminente foca no Aprendizado Federado Clusterizado
(do inglês, \textit{Clustered FederatedLearning} -- CFL).
A intuição por trás do CFL é agrupar clientes com distribuições de dados semelhantes e treinar modelos especializados para cada grupo.
Essa abordagem tem demonstrado melhorar significativamente o desempenho em ambientes heterogêneos.

No IFCA, proposto por Ghosh et al. \cite{ghosh2020efficient},
o servidor mantém múltiplos modelos globais e os transmite aos clientes.
Cada participante avalia os modelos recebidos com seus próprios dados e seleciona aquele que possui menor perda como base para o treinamento.
Terminado o treinamento, ele envia o modelo treinado de volta para o servidor junto do identificador de qual modelo usou.
No servidor, cada modelo global é atualizado somente com os clientes que os utilizaram para treinar.
O IFCA exige que o cliente se vincule estritamente a um grupo por rodada,
o que limita a possibilidade de usar conhecimento de outros grupos localmente.
Isso também limita contribuição do cliente na atualização do modelos globais,
já que só o modelo do grupo que ele escolheu vai se beneficiar.

Li et al. \cite{li2022federated} apresenta o Aprendizado Federado com Agrupamento Suave (FLSC) como uma melhoria do IFCA.
Essa melhoria possibilitou aos clientes pertencerem a múltiplos grupos simultaneamente.
Graças a isso, o FLSC demonstrou capturar melhor a natureza dos dados não-IID em relação ao seu antessesor~\cite{...}.
Contudo, o método impõe um número fixo de grupos para todos os clientes participarem,
e o peso de participação do cliente em qualquer grupo é sempre igual.
Isso ainda não reflete perfeitamente um cenário real.
Por exemplo, num sistema de recomendação,
conteudos do tipo A e B podem estar num cliente c1, enquanto outro cliente c2 tem conteudos do tipo B, C, D e E.
É natural pensar que c1 participe de menos grupos de recomendação que c2.
Além disso, não necessariamente todos conteúdos vão ser recomendados na mesma frequência.
Pode ser que c2 consuma muito conteudo do tipo B, consequentemente gerando muito mais dados do tipo B.
Logo faz sentido pensar que c2 participe bem mais do grupo que inclui conteudo do tipo B.

Visando superar as limitações do FLSC, este trabalho propõe o FLASC (\textit{Federated Learning with Adaptive Soft Clustering}).
Diferente do FLSC, o FLASC permite não só que a quantidade de grupos que um cliente participe se ajuste conforme a sua distribuição local,
como ele também pondera o peso de participação do cliente em cada grupo.
