\section{FLASC} \label{sec:flasc}

Esta seção detalha o funcionamento do algoritmo FLASC,
descrevendo os mecanismos de seleção adaptativa e fusão ponderada que o diferenciam do FLSC.
O Algoritmo \ref{alg:flasc} detalha o fluxo operacional completo do processo de treinamento federado.

\begin{algorithm}[H]
    \SetAlgoLined
    \KwIn{Parâmetros iniciais $K$, tolerância $\rho$, sensibilidade $\epsilon$}
    \KwData{Conjuntos de dados locais $\mathcal{D}_c$ nos clientes}
    \BlankLine
    \textbf{Servidor:} Inicializa $\mathcal{W}_1 = \{W_{1,1}, \dots, W_{K,1}\}$\;
    \BlankLine
    \For{cada rodada $t = 1, \dots, T$}{
        Servidor seleciona aleatoriamente um subconjunto de clientes $P_t$\;
        Servidor transmite $\mathcal{W}_t$ para todos os clientes em $P_t$\;
        \BlankLine
        \textbf{Cada cliente $c \in P_t$ em paralelo:}\\
        Calcula perdas locais $L_{c,i} = \text{EntropiaCruzada}(W_{i,t}, \mathcal{D}_c)$ para $i \in \{1, \dots, K\}$\;
        $L_{min} \leftarrow \min_i \{L_{c,i}\}$, $L_{max} \leftarrow \max_i \{L_{c,i}\}$\;
        \eIf{$L_{max} - L_{min} \leq \epsilon$}{
            $i' \sim \text{Unif}\{1, \dots, K\}$, $S_c \leftarrow \{i'\}$\;
            $\alpha_{c,i'} \leftarrow 1$\;
        }{
            $\hat{L}_{c,i} \leftarrow \frac{L_{c,i} - L_{min}}{L_{max} - L_{min}}$ para cada $i \in \{1, \dots, K\}$\;
            $S_c \leftarrow \{i \mid \hat{L}_{c,i} \leq \rho\}$\;
            $\alpha_{c,i} \leftarrow \frac{1 - \hat{L}_{c,i}}{\sum\limits_{j \in S_c} (1 - \hat{L}_{c,j})}$ para cada $i \in S_c$\;
        }
        $W_{c,t} \leftarrow \sum\limits_{i \in S_c} \alpha_{c,i} W_{i,t}$\;
        $W_{c,t}^{end} \leftarrow \text{TreinamentoLocal}(W_{c,t}, \mathcal{D}_c)$\;
        Envia $\{W_{c,t}^{end}, S_c\}$ para o servidor\;
        \BlankLine
        \textbf{Servidor:}\\
        \For{cada cluster $i \in \{1, \dots, K\}$}{
            \eIf{$\{c \in P_t \mid i \in S_c\} \neq \emptyset$}{
                $W_{i,t+1} \leftarrow \frac{\sum\limits_{c \in \{j \in P_t \mid i \in S_j\}} |\mathcal{D}_c| W_{c,t}^{end}}{\sum\limits_{c \in \{j \in P_t \mid i \in S_j\}} |\mathcal{D}_c|}$\;
            }{
                $W_{i,t+1} \leftarrow W_{i,t}$\;
            }
        }
    }
    \caption{Algoritmo FLASC}
    \label{alg:flasc}
\end{algorithm}

Tanto o FLASC quanto o FLSC gerenciam um conjunto de $K$ modelos globais no servidor,
representados por $\mathcal{W}_t = \{W_{1,t}, W_{2,t}, \dots, W_{K,t}\}$.
No início de cada rodada de treinamento, o servidor seleciona uma fração de clientes para participação e realiza a transmissão de $\mathcal{W}_t$.
Uma vez recebidos os modelos, cada  participante $c$ mensura o desempenho de cada modelo
calculando a Entropia Cruzada em relação ao seu conjunto de dados local $\mathcal{D}_c$ (Linha 6).

\subsection{Seleção dos modelos no cliente}

A partir das perdas calculadas, o FLASC avalia a amplitude entre a maior e a menor perda (Linha 8).
Se essa diferença for inferior ao limiar de sensibilidade $\epsilon$,
os modelos são considerados indistinguíveis para o cliente e um único modelo é selecionado aleatoriamente (Linha 9).
Caso contrário, as perdas são normalizadas no intervalo $[0, 1]$ (Linha 12).

Em seguida, define-se o conjunto $S_{c}$ dos índices dos modelos selecionados através do limiar $\rho \in [0, 1]$ (Linha 13).
Este limiar estabelece um teto de tolerância para as perdas,
assegurando que apenas os modelos com desempenho suficientemente próximo ao melhor candidato componham o conjunto de fusão.
Diferentemente do FLSC, onde o tamanho do conjunto de seleção $N$ é fixado a priori,
o FLASC permite uma seleção adaptativa, evitando a inclusão de modelos com erros excessivos apenas para satisfazer uma restrição de cardinalidade.
Adicionalmente, para cada modelo selecionado, o FLASC atribui um peso de contribuição $\alpha_{c,i}$ que decresce linearmente em função da perda normalizada (Linhas 10 e 14).
Este mecanismo garante que modelos com menor erro local exerçam maior influência na fusão, funcionalidade que não é contemplada na formulação original do FLSC.

\subsection{Fusão, treinamento e agregação}

Concluída a etapa de seleção, o cliente sintetiza o modelo inicial para o treinamento local
$W_{c,t}$ mediante uma média ponderada (Linha 16).
Após o treinamento local, os parâmetros atualizados ($W_{c,t}^{end}$) são devolvidos ao servidor acompanhados de $S_c$ (Linhas 17-18).
Ao término da rodada, o servidor atualiza os modelos globais de forma independente (Linhas 20-26).
Para cada cluster $i$, a nova versão $W_{i,t+1}$ é obtida por meio de uma média ponderada
das atualizações enviadas pelos clientes que usaram o respectivo modelo em sua fusão local.
Caso $W_{i,t}$ não tenha sido selecionado por nenhum cliente, seus parâmetros permanecem inalterados.
